# 需求与设计决策

状态：已确认来自用户明确要求；设计推荐仍需评审/实测；实现不等于所有平台已验收。当前源码 0.1.1 已通过官方预审并按用户授权发布 GitHub Release；目录发布后审查完成，公开版本为 0.1.1，Review 为 Satisfactory。普通库入口和设备接入已实现，生产验收仍未完成。历史测试结果已清理，本文保留有效合同和技术边界。

## 架构与当前实现

用户确认本次生产服务器使用 PostgreSQL，部署文档明确 SQLite 尚未实现，不新增虚假的 SQLite Compose。部署使用独立 `xsync-server` Compose 项目，服务端加入已有 Nginx 代理网络且启用 TLS，PG 仅在内部数据库网络，两者均不映射宿主端口。库初始化与同步密钥仍由所有者电脑生成；服务端私有运行配置可包含数据库 DSN，但不能包含同步密钥。原 CouchDB 数据保留，不进行自动迁移。

服务端镜像与插件分开打包：Go 静态二进制、Linux amd64/arm64、非 root 用户；配置、同步密钥和数据不进入构建上下文。CI 完整验证通过后才允许 Docker Hub 上传；普通 push/PR 只验证，手动发布使用 edge/准确版本，正式 GitHub Release 更新版本与 latest。容器保持现有监听安全合同，Linux host 网络可复用宿主 loopback HTTPS 代理与 Docker PG；其他网络方式需 TLS 配置，不开放生产明文非 loopback。部署与凭据配置见 [DEPLOYMENT](DEPLOYMENT.md)、[RELEASING](RELEASING.md)。

TypeScript 插件、IndexedDB/Dexie、本机加密暂存、独立协议、Go/pgx、Docker PostgreSQL 元数据与不可变密文对象。普通文件用 Vault API，隐藏配置用 Adapter 和实际 configDir；移动核心不依赖 Node/Electron。

文件身份、位置与内容版本分离；编辑只基于实际展示的准确修订。未知来源的同路径内容保留独立根，不借用远端版本当祖先。明确拒绝的初始化 create 先归档原 intent/identity/journal 再核对，复杂或未知提交不猜测修复。

outbox 先持久化不可变意图；重试先询问幂等回执，缺对象时认证本地密文后上传。received 与 inbox 一起提交，applied 独立推进；文件应用用加密 stage/备份与 journal 恢复，不声称 DB、文件、网络是跨系统事务。日志过期只接受同 epoch、不回退且完整的认证快照，保留本机任务与字节。

设备安全存储保护本机解锁材料，不明文保存口令或会话密钥。桌面使用 safeStorage；iOS 内部 SecureStorage 桥接按自有 namespace 保存随机包装密钥，逐次请求 sync=false / WhenUnlockedThisDeviceOnly，并做身份绑定 AEAD 和写后读回。缺少桥接拒绝保存，无 web 明文回退。暂时不可读时前台重试，原记录保留。

实验加密格式为 keyEpoch=1：libsodium 用途隔离派生/路径索引、Argon2id13 包装、XChaCha20-Poly1305。生产格式/参数与迁移未冻结，不能静默重建已有实验数据。桌面结果不代替手机安全访问、备份迁移或原生内存证据。

名称按 NFKC/case-fold 判重，改名不改变身份；服务器 CAS 保护加密配置快照。RE2JS 不支持回溯引用/前后查找；硬上限 100 MB 为 100,000,000 字节，传输块为 4 MiB。源文件仍整读，未知第三方私密字段不能靠通用规则保证识别。

开发 PG 一律 Docker，仅本项目容器/volume，禁止宿主 PG。默认 HTTP 仅 loopback；测试 LAN 需显式开关、私有 IP、隔离 schema 和预置精确 origin。iOS WS Origin 精确允许 capacitor://localhost，仍需票据认证。正式非 loopback 监听要求 TLS，或由已有 HTTPS 代理转发至 loopback；已提供独立 Docker PG 配置和运维说明，尚未实际部署验收。

## 设备接入决策

所有者在自己的电脑生成随机 256 位同步密钥、vault/epoch、密文密钥包和用途隔离的 Ed25519 验证公钥；只把公开初始化包送到服务端，禁止服务器保存同步密钥。普通库自行生成设备/IndexedDB 身份，不预置令牌、不要求开发标记。旧测试 fixture 仍仅在自有标记下接受精确 LAN 例外。

客户端本地解密后签署一次性挑战，签名绑定 vault/epoch、挑战 ID/nonce、设备 ID、名称及令牌 SHA256；跨语言使用长度前缀 UTF-8。服务端只保存公钥和令牌摘要。新令牌及准确签名请求先由系统保护并持久化，再提交接入；成功回执丢失时重试同一请求，公开设置指针失败时保留待确认记录。已有本地修订/epoch 在授权前校验，不以换身份掩盖恢复问题。

第一台设备成功后默认关闭接入，后续由本机 CLI 开放最长一小时的窗口。挑战有效 90 秒，未完成挑战上限 128，设备记录上限 256（包括撤销）。名称唯一检查与接入在数据库事务内串行。撤销 ID 永久保留，服务重开不复活；HTTP 新请求与事件提示/心跳校验撤销和令牌更换。已执行中的请求不承诺原子撤回。

安全存储永久丢失但仍持有同步密钥时，在接入窗口内允许同一 ID 更换授权令牌，保持本地因果身份；这不是内容密钥轮换。撤销不抹去已同步明文或共享密钥；共享密钥持有者仍可能在未来窗口用新 ID 接入，泄露后的内容密钥迁移尚未实现。

## 核心不变量

1. 接受版本的内容引用耐久存在且可校验，上传损坏暂存不能污染不可变对象。
2. op_id 与请求摘要绑定，重试不产生重复版本或副本。
3. 接收游标与待应用任务一起持久化；应用游标不越过未完成任务。
4. 文件不匹配准确快照时保留字节和任务，不能虚报完成。
5. 扫描/权限错误不是删除证据，单文件失败不阻塞无关文件；锁定/失去租约停止整轮。
6. 重命名目标失败不删除源；多文件操作按 journal 恢复，不冒充文件系统事务。
7. 冲突、历史、活动任务、快照和备份依赖在未来 GC 中必须受保护。
8. 服务端旧备份恢复须核对 epoch；客户端不自动服从回退远端。
9. 错误密钥/未知协议只阻止操作，不触发远端初始化或重建。
10. 未解决冲突或失败任务显示需处理；所选范围完成不表示整库历史已收敛。
