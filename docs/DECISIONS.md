## 架构与当前实现

用户确认本次生产服务器使用 PostgreSQL，部署文档明确 SQLite 尚未实现，不新增虚假的 SQLite Compose。部署使用独立 `xsync-server` Compose 项目，服务端加入已有 Nginx 代理网络且启用 TLS，PG 仅在内部数据库网络，两者均不映射宿主端口。库初始化与同步密钥仍由所有者电脑生成；服务端私有运行配置可包含数据库 DSN，但不能包含同步密钥。原 CouchDB 数据保留，不进行自动迁移。

服务端镜像与插件分开打包：Go 静态二进制、Linux amd64/arm64、非 root 用户；配置、同步密钥和数据不进入构建上下文。CI 完整验证通过后才允许 Docker Hub 上传；普通 push/PR 只验证，手动发布使用 edge/准确版本，正式 GitHub Release 更新版本与 latest。容器保持现有监听安全合同，Linux host 网络可复用宿主 loopback HTTPS 代理与 Docker PG；其他网络方式需 TLS 配置，不开放生产明文非 loopback。部署与凭据配置见 [DEPLOYMENT](DEPLOYMENT.md)、[RELEASING](RELEASING.md)。

TypeScript 插件、IndexedDB/Dexie、本机加密暂存、独立协议、Go/pgx、Docker PostgreSQL 元数据与不可变密文对象。普通文件用 Vault API，隐藏配置用 Adapter 和实际 configDir；移动核心不依赖 Node/Electron。

文件身份、位置与内容版本分离；编辑只基于实际展示的准确修订。未知来源的同路径内容保留独立根，不借用远端版本当祖先。明确拒绝的初始化 create 先归档原 intent/identity/journal 再核对，复杂或未知提交不猜测修复。

outbox 先持久化不可变意图；重试先询问幂等回执，缺对象时认证本地密文后上传。received 与 inbox 一起提交，applied 独立推进；文件应用用加密 stage/备份与 journal 恢复，不声称 DB、文件、网络是跨系统事务。日志过期只接受同 epoch、不回退且完整的认证快照，保留本机任务与字节。

设备安全存储保护本机解锁材料，不明文保存口令或会话密钥。桌面使用 safeStorage；iOS 内部 SecureStorage 桥接按自有 namespace 保存随机包装密钥，逐次请求 sync=false / WhenUnlockedThisDeviceOnly，并做身份绑定 AEAD 和写后读回。缺少桥接拒绝保存，无 web 明文回退。暂时不可读时前台重试，原记录保留。

实验加密格式为 keyEpoch=1：libsodium 用途隔离派生/路径索引、Argon2id13 包装、XChaCha20-Poly1305。生产格式/参数与迁移未冻结，不能静默重建已有实验数据。桌面结果不代替手机安全访问、备份迁移或原生内存证据。

名称按 NFKC/case-fold 判重，改名不改变身份；服务器 CAS 保护加密配置快照。RE2JS 不支持回溯引用/前后查找；硬上限 100 MB 为 100,000,000 字节，传输块为 4 MiB。源文件仍整读，未知第三方私密字段不能靠通用规则保证识别。

开发 PG 一律 Docker，仅本项目容器/volume，禁止宿主 PG。默认 HTTP 仅 loopback；测试 LAN 需显式开关、私有 IP、隔离 schema 和预置精确 origin。iOS WS Origin 精确允许 capacitor://localhost，仍需票据认证。正式非 loopback 监听要求 TLS，或由已有 HTTPS 代理转发至 loopback；已提供独立 Docker PG 配置和运维说明，尚未实际部署验收。

## 同步内部数据清理（第一步已实现，尚未发布）

用户已确认只做多设备文件同步和冲突处理，包括单方/双方离线修改。不做历史版本、历史恢复、版本收藏或独立回收站；旧 architecture HTML 中的 90 天历史与恢复规划由本节替代，原稿保留，不代表现行产品合同。普通文件删除继续遵循 Obsidian 的删除设置，不清空宿主或系统回收站。

第一步仅处理本机已完成数据，入口为 `plugin/src/sync/local-cleanup.ts`。同步轮应用结束、或显式冲突解决成功后，在当前引擎串行执行及有效本机租约下执行：

- 仅删除 `done=true` 且 `seq <= applied` 的 inbox；记录删除和依赖检查在同一 IndexedDB 事务中完成。接收游标不能代替应用完成，进度之后的已完成条目也暂留。
- 私有 staging 先枚举候选，再读取持久化依赖。保留全部 outbox（含排除/失败）、待应用任务及备份、拒绝记录、未结束核对归档、冲突头与未完成 inbox 的引用。修订记录自身不永久保护已确认上传的本机副本。
- 元数据事务提交后，逐个检查租约、永久删除无依赖的暂存文件。仅操作本设备私有 staging 的直接合法 ID 文件，不递归、不触碰笔记、身份、密钥或宿主回收站。阶段 ID 不用于新操作复用；候选枚举在依赖检查之前，避免把之后写入的新阶段纳入本轮删除。
- 应用确认前重新读取并核对实际结果指纹；删除核对源已不存在，移动核对目标内容和源已不存在。宿主写入返回成功但实际内容不完整时保留 journal/备份，不推进完成边界，不释放恢复材料。
- 清理中断或 I/O 失败可重试；删除失败保留剩余文件并报告诊断，不重放已确认上传。未获租约、授权/密钥核对失败或同步暂停时，不启动清理。
- 初始化路径碰撞归档记录目标文件 ID。只有原身份已退出、目标没有待提交/应用/冲突/草稿，并且目标当前服务端版本及其祖先中包含原内容准确指纹（包括已存在的相同远端内容），才删除该归档及准确对应的碰撞拒绝记录。兼容旧归档按原路径身份查找；含归档 journal、未接受内容、未知原因或未确认结果一律保留。过期选择 `REVIEW_STALE` 的证据继续保留，不能仅凭其他设备解决冲突就清除未提交的合并内容。

第一步仅清理本机已完成数据；第二步服务端清理见下节。这两步原先保留因果修订和全部幂等回执；现行修订/位置/回执与本机缓存压缩由下文第三步 3B 扩展，不能直接裁断父子关系或改写已认证修订。删除记录和旧格式对象身份仍保留；3C 新格式身份回收见后文，不保证所有内部元数据总量恒定。

长期回归入口：`tests/desktop/local-cleanup.test.ts` 覆盖依赖集合、共享引用、事务回滚、删除失败、租约失效与归档完成证明；`recovery.integration.test.ts` 覆盖真实文件/HTTP/Docker PG 的清理重试与离线冲突；`recovery-browser.integration.test.ts` 覆盖原生 IndexedDB 清理边界的进程强杀。测试结果写入忽略目录，自动测试不代替手机真机验证。

## 服务端内容生命周期（第二步已实现，尚未发布）

范围继续限定为同步与冲突处理，不提供历史版本或回收站。第二步原先保留全部随机对象身份、摘要和长度；3C 进一步回收新格式对象身份，旧格式身份作为迁移成本保留，实际密文仍按依赖回收。第二步原先完整保留修订/位置/回执；第三步 3B 已扩展这些元数据的压缩，见下节。不可变修订的内容和认证上下文始终不改写，旧修订的对象引用不承诺对应密文永久可下载。

- `content-leases-v1` 是插件与服务端必须共同支持的能力。HTTP 同步端点强制检查 `X-Sync-Content`，旧客户端得到 `CLIENT_UPGRADE_REQUIRED`；仅追加 handshake feature 不足以保护旧客户端。协议能力放在请求头，升级前已持久化的 outbox 正文保持不变，原 op_id/摘要仍有效。现有已发布 0.1.2 插件不能与本轮新服务端同步，须使用配套新构建；本轮不发布、不部署。
- 上传保护绑定设备、库、epoch、原提交请求与对象集合；重复请求复用有效保护，正文不同则拒绝。上传只发布已 fsync 的准确密文；未完成的上传代次不被提交接受。先查成功回执，再校验本次对象，旧密文已清理时仍返回原回执。保护到期后，未成功提交的原请求可用原 ID/准确密文重新上传。
- 下载保护只接受当前版本头，或该设备有效快照冻结的版本头，并绑定对象存储代次。一个有界块读取到内存期间持有短数据库锁，网络发送在释放锁后进行。块集合认证完成后客户端释放下载保护；此后的本机暂存/应用任务不依赖远端旧密文。活动保护默认 5 分钟，客户端在继续传输前按一分钟间隔续期；完成主动释放，断网/强退按到期处理，释放请求最多等待 3 秒。
- 快照生成、保存及冻结头的保护登记处于同一库锁/事务。创建请求 ID 幂等，每设备最多两个有效快照。3B 启用后快照只携带当前版本头及基线凭据，仅冻结版本头的字节受保护；活动下载会续期。过期快照及对应保护由维护任务删除，客户端改取新快照；保留本机 outbox、未完成应用任务和原文件。密文/清单认证失败属于真实错误，不能作为正常过期吞掉。
- 日志仅补齐同步元数据，不永久保护旧事件的文件内容。默认最多 7 天、10,000 个提交组、64 MiB 日志 JSON；达到任一上限，删除最老连续前缀，同时在同一事务推进 `min_seq`。截断前用与快照创建相同的编码检查客户端上限（10,000 文件、100,000 当前头修订、32 MiB）；超限时回滚本轮维护、保留日志并报告，避免切断补齐路径。落后设备走 `NEED_SNAPSHOT`，无需等待所有离线设备确认。下载视图过期时同步轮最多刷新两次，再保留任务并报告错误。
- 密文状态为 ready → candidate → deleting → deleted。仅当前全部版本头（含未解决冲突）、有效上传/下载/快照保护是保留根；无依赖内容默认宽限一小时，再在库锁内复查并登记删除任务。候选重新被使用则取消候选。登记 deleting 后不接受该代次的新引用；磁盘删除、目录 fsync、数据库确认分步持久化，失败/重启可重试。
- 删除任务绑定物理存储代次：旧数据及首次上传使用原 ID 路径，重新上传使用 `.gN` 路径。摘要与公共对象 ID 始终绑定原密文，旧删除任务只操作旧代次，不会删除新上传。上传尝试在写文件前登记；仅清理已知失效尝试的旧代次/临时文件，未知遗留文件不按修改时间自动删除。
- 服务进程默认每分钟运行维护，启动先核对当前头密文的 SHA256/长度；核对失败则停止自动维护并报告，不清理当前头。`cleanupMode` 可为 `on`（默认）、`dry-run`（仅统计密文候选，不修改数据）或 `off`；三种模式均要求新内容协议。管理员可用 `--cleanup-once` 执行一轮，配合 `--cleanup-dry-run` 只检查，配置的 `dry-run` 也约束手动维护；`off` 仅停止自动调度。普通管理命令不启动维护。停服等待维护退出后再联合备份，仍不提供在线备份功能；不能回退旧程序直接读写本轮 schema/已回收数据。

入口：`server/internal/syncstore/leases.go`、`cleanup.go`、`objects.go`、`http.go`，客户端 `transport.ts`/`engine.ts`。长期验证源码包括 Go 真实 Docker PG 合同/race、回收并发和故障边界；`content-lifecycle.integration.test.ts` 的真实回收及维护进程 SIGKILL；原生 IndexedDB 的清理后离线重连。测试仍不代替手机真机、大库性能或联合备份还原验收。

## 元数据压缩前置协议（第三步 3A 已实现，尚未发布）

用户已批准第三步按 3A（基线凭据、请求流、完成确认）、3B（修订/位置/本机缓存压缩）、3C（新对象格式与身份回收）依次推进。3A 已完成；以下记录其前置合同。3B/3C 已在工作区实现，各自覆盖及迁移边界见后文；尚未发布或部署，不将自动化验证报告为真机/联合备份还原验收。

- 新能力为 `metadata-anchors-v1`。新客户端要求服务端支持，metadata HTTP 端点同时校验 `X-Sync-Metadata` 和第二步的 `X-Sync-Content`；本阶段保留第二步内容协议的旧提交入口，不封闭旧协议、不裁剪原图。原 outbox 请求正文不变，请求流/序号与基线证明放在外层提交信封；升级前队列只补本机坐标，不修改 op_id、父修订或捕获字节。
- 服务端以独立 HMAC-SHA256 认证密钥签发已接受基线凭据，绑定 vault/epoch、file_id、revision_id、原修订规范摘要和签发时进度；不包含解密密钥。密钥在库锁事务中生成一次，保存在 PG 私有 `metadata_auth`，初始化标记已存在而密钥缺失则拒绝启动，不静默重新生成。联合备份必须包含该表；备份还原/轮换仍需独立验收。
- 客户端先认证原修订密文清单，再验证凭据的文件、修订、epoch 和摘要。应用/接入准确相同内容前保存展示基线；自身成功提交得到准确修订凭据。错误凭据不作为普通视图过期处理，保留文件与任务。
- 每个设备在每个库内有独立持久请求流和安全整数序号。坐标分配与 outbox 写入事务化；原请求重试沿用坐标。序号只防重复，不决定因果关系或冲突赢家。旧成功回执先于基线重新验证，避免已接受请求因旧依赖变化被重新执行。
- 服务端跟踪成功请求的准确摘要、回执和基线结果，记录与数据提交同事务。客户端在同一 IndexedDB 事务中保存已认证结果、最高已见服务端进度、待发送确认，并移除 outbox，随后才发送确认。确认响应丢失保留本机确认账本，重启重试；确认成功后释放服务端跟踪结果副本和本机账本，3A 阶段原 `operations` 证据暂不删除，3B 的新回执回收见下一节。
- 完成确认按连续前缀加稀疏区间合并，不能用最大成功序号跳过排除/失败请求。已退休序号不能再执行；确认重复是幂等无操作。每设备最多 4096 个未确认跟踪结果，达到上限先补确认，不按时间抹去未确认结果。
- 客户端保存序号下次分配位置和最高已接受/签发进度。请求流不符、计数回退或服务端进度回退时保留本机字节和队列，进入恢复核对，不自动重置计数、换设备身份或借用当前远端版本作祖先。
- 3A 阶段每个新提交由完整图算法计算头集合，同时用独立直接父版本投影比较；不一致则事务回滚。属性测试用独立极大节点图 oracle 覆盖根导入、基于任意旧版本的编辑与显式合并；本阶段影子校验不代表已切换成压缩图实现。

入口：`server/internal/syncstore/metadata.go`、客户端 `metadata-client.ts` 与 `protocol/src/metadata.ts`。本机 schema v5 增加 writerState/baseProofs/requestAcks，兼容旧状态，不清空库。长期回归包含 Go 真实 Docker PG 合同/race、跨语言凭据、完成确认丢失与区间空洞、计数回退、原生 IndexedDB 四个新增确认强杀边界；截图/日志仍只放忽略目录，未做真机或生产验收。

3A 当时保留完整图作影子对照；下面的 3B 扩展并替代其中“主元数据不删除”的阶段性限制。3C 已加入新密文标识/认证上下文和随机物理存储代次，见后文；不能直接删除第二步随机对象 ID 的身份行。

## 修订、位置与本机缓存压缩（第三步 3B 已实现，尚未发布）

继续只做同步与用户决定的并发/离线冲突，不做历史版本、历史恢复或回收站。3B 新增 `compact-heads-v1`，客户端要求服务端支持；已切换的服务端同时强制 `X-Sync-Compaction`，配套新插件/服务端才能同步。工作区没有发布、部署或操作真实笔记库。

- 默认首次打开数据库，在库锁事务内建立旧接受索引并记录 `metadata_checkpoint`。索引保存旧 revision 的 ID/file/原规范摘要、旧 location ID；原成功 `operations` 摘要/回执保留。一次迁移分批读取旧修订，不将全部旧正文累计到内存。检查点独立于 vault epoch，不重置 seq 或文件身份。`metadataMode=full` 只用于切换前暂缓和完整图对照；已切换库拒绝降回 full；本轮程序已经打开的 full 实例会按数据库模式变化拒绝同步写入。旧版二进制不理解该检查点，仍必须停服后配套升级，禁止并行运行或回退旧程序。
- 每设备首次连接 3B 时，客户端先持久化升级前原 outbox 登记包，服务端一次登记准确请求摘要，响应丢失重发相同包，之后本机清空包正文并保留完成标记。排除/失败队列也登记；每设备最多 4096 项、单包 HTTP 上限 32 MiB，超限保留原队列并拒绝登记。旧正文、op_id、父版本和暂存字节不重写。新 legacy 请求必须在这份已封闭登记中；恢复出登记之外的旧意图保留原字节/队列并要求核对，不能自动换父或重新捕获当前 Vault 字节。
- 新 op_id、revision ID 和 location ID 由持久请求流、序号、动作序号及独立角色派生，服务器逐项校验。companion 使用独立角色，file ID 仍随机且删除身份保留。退休序号不重放，其他序号不能复用旧 revision/location ID；因此新编辑不再追加永久 used-ID 索引。已登记的旧随机 ID 意图接受时补入旧索引，规模只来自迁移前已接受数据和一次登记的旧队列。
- 编辑只移除当前头中等于实际展示父版本的项，再加入新版本；已接受旧父不在当前头时形成并发分支。服务端以完整原修订或基线凭据确认合法旧父，旧接受索引可为升级前完整原修订补签凭据。解决仍要求准确完整头集合及位置 CAS，不能由时间、顺序或超时选赢家。保留独立投影检查，并用完整图 oracle 对照每步裁剪后的实现。
- 快照只包含所有文件/删除身份、当前全部头和对应凭据，保留原修订完整认证上下文，不递归携带祖先。服务端提交和快照只加载当前头/当前位置正文；客户端原子保存快照、凭据和接收游标。日志过期继续取快照，checkpoint/epoch/seq 回退或协议降级保留本机材料并拒绝自动继续。
- 维护事务在日志前缀/过期快照回收后，保留当前头、尚在保留期内的日志所产生修订，以及有效冻结快照的头；删除其余完整修订和对应 `revision_objects` 边，只保留当前位置正文。未确认提交结果自带完整原修订与凭据，不依赖其主表行仍在；旧成功回执按准确原请求重建同一结果，不能重新执行。新派生 ID 请求的原 `operations` 与跟踪副本在完成确认事务中一起释放；迁移前/登记旧意图的回执仍保留。
- 本机 schema v6 增加一次迁移状态。清理与依赖检查同事务，保留本机展示基线、当前远端/冲突头、全部 outbox（含排除/失败）、拒绝意图、未完成 inbox、应用任务、核对归档和待确认迁移包引用；删除其他修订/凭据，不递归保留 parent/selectedFrom 字符串。当前唯一头只有在本机基线已接受、没有该文件待上传工作且实际字节仍匹配时才能应用；未接受本机版本不能当作可覆盖基线。
- 初始化碰撞归档在存在其他未完成工作时持久保存“原准确字节已被目标文件接受”的修订凭据引用，之后不依赖已裁剪祖先判断完成。原未接受内容、未知拒绝、过期选择和 archived journal 继续作为恢复材料保留，不按时间删除。

正常已完成编辑的修订正文/位置/新回执随当前文件、冲突、保留日志、有效快照与待处理工作收敛；不宣称全部元数据恒定。旧接受索引及旧回执是迁移成本，文件删除身份和永久撤销设备仍保留，失败序号产生的稀疏确认区间与未完成恢复证据也可能积累。3C 已回收新格式对象身份；旧格式随机 ID/摘要仍保留为迁移成本。

入口：服务端 `compaction.go`/`cleanup.go`/`metadata.go`，客户端 `metadata-client.ts`/`metadata-cleanup.ts`/`projection.ts`。长期回归包含真实 PG 连续编辑/移动和退休重放、旧基线/旧成功结果、有效冻结快照、事务回滚，完整图对照、真实双端升级前队列/较新磁盘字节、确认/登记响应丢失，以及客户端原生 IndexedDB 和维护进程 SIGKILL。自动化不代替手机真机、大库性能或联合备份实际还原。

## 密文对象格式与身份回收（第三步 3C 已实现，尚未发布）

范围仍只有同步和显式冲突处理，不提供历史版本、历史恢复或回收站。新能力为 `addressed-objects-v1`；全部 HTTP 同步端点（包括 full 元数据模式）要求 `X-Sync-Objects`，避免旧客户端接收到不能解析的新对象引用。旧 Commit 正文仍不改写，能力放在外层请求头；新旧插件/服务端必须配套，旧二进制仍需停服升级，不能并行运行或直接回退。

- 新捕获对象 ID 为 `c_<SHA256(完整密文字节)>`。对象使用 XChaCha20-Poly1305、随机 nonce 和独立 `object-v1` 认证上下文，绑定 vault/keyEpoch，JSON envelope v=1；认证上下文不包含尚未产生的密文哈希 ID，避免循环依赖。相同明文重复捕获仍随机加密，不变成确定性明文去重。修订 manifest 继续认证对象 ID 列表。客户端与服务端都校验密文哈希对应 ID；正确响应摘要不能掩盖错误对象 ID，AEAD/格式错误不能作为正常过期吞掉。
- 旧 64 位随机 ID / `object-v0` / envelope v=0 仍可读、仍按原 ID 认证。生产新捕获只写 v1；不批量重加密旧对象，不修改已接受修订或 outbox 的 ID、正文和捕获字节。单个 manifest 可引用新旧对象。旧格式的 ID/摘要/长度及数值代次不能直接忘掉，回收字节后仍保留该身份摘要，准确旧重试仍受不可变约束。
- compact 模式为旧对象单独登记一次设备迁移包，独立于 3B 的旧请求登记：3B 已关闭后产生的 v0 待上传对象也能迁移。客户端 schema v7 在 `metadataMigration` 的 `objects` 行先持久化原 outbox 包，再提交，成功后清空正文并保存完成标记；响应丢失重发同包，原生确认边界可强杀重试。每设备最多 4096 请求、32 MiB 包，超限保留原队列并拒绝。已有旧身份允许准确复用；尚未被服务端认识的旧随机 ID 必须来自这份登记，否则保留原意图/字节并报告，其他文件可继续同步。full 模式只用于迁移前暂缓/完整图合同，不承诺旧元数据有界。
- 新格式物理路径为 `<c_ID>.s<随机 storage_token>`，每次重新预约上传产生新的 256 位标识，即使对象身份主行已被清理也不复用旧物理路径。上传尝试、读/快照保护和删除任务都持久绑定准确标识；旧格式继续兼容原 ID / `.gN` 路径和单调数值代次。公开对象 ID 与磁盘路径分开，不用对象表行存在或计数未归零来保证删除安全。
- 上传先持久化预约/尝试，再在库锁中复查准确代次/标识、有效尝试和保护，之后才创建临时文件。锁覆盖单个有界密文块的写入、fsync、发布和数据库完成，网络传输不在锁内；文件系统与 PG 仍是分别完成的边界。临时硬链接删除及目录 fsync 必须先于释放数据库尝试登记，防止确认后强退留下无登记文件。已过期且清理的旧上传者恢复时在创建文件前拒绝，不重新产生已遗忘的物理文件。
- 保留根为当前全部头 JSON 的实际对象引用及有效上传/读/快照保护；派生 `revision_objects` 索引缺失不能让当前内容失去保护。启动核对从原头 JSON 读取对象，缺对象/损坏时拒绝自动维护。宽限和持久删除任务仍沿用第二步；磁盘 unlink/目录 fsync 完成后，在同一确认事务里清理新格式对象的非当前头派生边、删除任务和身份主行。旧修订 JSON 中的对象字符串不改写，也不承诺旧字节永久可下载。
- 删除确认前/后强退可重试；延迟旧删除者只能操作原随机物理路径，不能确认或移除新标识的任务。已知失效上传尝试按准确物理标识清理，身份主行已不存在也能完成；未知遗留文件仍不按修改时间删除。新对象完全回收后，原未接受 outbox 可从准确暂存重新上传同一密文字节/ID，得到新物理标识；已接受未确认结果仍从持久回执返回，不重新执行原操作。

正常已完成编辑的主修订/位置/新回执、新格式对象身份与密文，按当前文件、未解决冲突、保留日志、有效保护和未完成工作收敛。旧修订接受索引、旧回执、旧格式对象摘要、删除文件/撤销设备身份和失败确认空洞仍可能长期保留，不声称所有内部记录恒定。清理验证指逻辑行与文件依赖，未证明大库下 PG 文件占用或手机资源表现。

入口：`protocol/src/objects.ts`、客户端 `crypto.ts`/`metadata-client.ts`/staging 适配，服务端 `object_address.go`/`objects.go`/`cleanup.go`。长期回归覆盖 SHA256 跨库校验、真正 v0 密文/版本替换拒绝、旧队列在 3B 已登记后的迁移、登记丢失、未知旧意图保留、新对象连续回收、重上传和旧删除者、迟到上传者、头索引缺失，以及实际子进程在预约/fsync/发布/确认处 SIGKILL、维护身份回收和原生 IndexedDB 强杀。密钥轮换、联合备份实际还原、真机和生产安全验收仍待完成。

## 设备接入决策

所有者在自己的电脑生成随机 256 位同步密钥、vault/epoch、密文密钥包和用途隔离的 Ed25519 验证公钥；只把公开初始化包送到服务端，禁止服务器保存同步密钥。普通库自行生成设备/IndexedDB 身份，不预置令牌、不要求开发标记。旧测试 fixture 仍仅在自有标记下接受精确 LAN 例外。

客户端本地解密后签署一次性挑战，签名绑定 vault/epoch、挑战 ID/nonce、设备 ID、名称及令牌 SHA256；跨语言使用长度前缀 UTF-8。服务端只保存公钥和令牌摘要。新令牌及准确签名请求先由系统保护并持久化，再提交接入；成功回执丢失时重试同一请求，公开设置指针失败时保留待确认记录。已有本地修订/epoch 在授权前校验，不以换身份掩盖恢复问题。

第一台设备成功后默认关闭接入，后续由本机 CLI 开放最长一小时的窗口。挑战有效 90 秒，未完成挑战上限 128，设备记录上限 256（包括撤销）。名称唯一检查与接入在数据库事务内串行。撤销 ID 永久保留，服务重开不复活；HTTP 新请求与事件提示/心跳校验撤销和令牌更换。已执行中的请求不承诺原子撤回。

安全存储永久丢失但仍持有同步密钥时，在接入窗口内允许同一 ID 更换授权令牌，保持本地因果身份；这不是内容密钥轮换。撤销不抹去已同步明文或共享密钥；共享密钥持有者仍可能在未来窗口用新 ID 接入，泄露后的内容密钥迁移尚未实现。

## 核心不变量

1. 当前有效版本及有效内容保护引用的密文耐久存在且可校验；上传损坏暂存不能污染不可变对象。旧修订关系保留不代表旧字节永久可下载。
2. op_id 与请求摘要绑定，重试不产生重复版本或副本。
3. 接收游标与待应用任务一起持久化；应用游标不越过未完成任务。
4. 文件不匹配准确快照时保留字节和任务，不能虚报完成。
5. 扫描/权限错误不是删除证据，单文件失败不阻塞无关文件；锁定/失去租约停止整轮。
6. 重命名目标失败不删除源；多文件操作按 journal 恢复，不冒充文件系统事务。
7. 当前有效版本、冲突和有效内容保护在服务端 GC 中受保护；备份采用停服联合边界，不设用户历史保留范围。
8. 服务端旧备份恢复须核对 epoch；客户端不自动服从回退远端。
9. 错误密钥/未知协议只阻止操作，不触发远端初始化或重建。
10. 未解决冲突或失败任务显示需处理；所选范围完成不表示范围外分支已解决。

同步状态展示以当前活动阶段和队列为准：核对、上传、接收、应用期间不能因队列暂为空而显示完成，也不沿用上一轮失败作为本轮正在上传的主状态。真实冲突持续提示处理；普通操作失败保留诊断，不能直接解释为人工冲突。队列清空且本轮结束后才显示所选范围完成。

## 访问 key 与库加密密码分离（行为已确认，HTML 待评审，未实现）

用户确认改为管理员集中发放访问 key：部署时通过环境变量配置管理端登录密码，管理员在 Web 后台创建用户，每个用户一个有效访问 key。key 仅生成时展示完整值，可刷新、停用和删除；刷新保持用户身份及库不变，使旧 key 和旧设备授权失效；停用保留数据，删除用户意味着删除其所属远端库，设备上的本地文件不远程擦除。具体部署变量、登录安全机制、删除和会话失效的实现仍需设计验证。

访问 key 只约束服务访问，不承担内容解密。用户首次创建远端同步库时，在插件本机设置独立的库加密密码，初始化完成后才开始上传；另一设备明确选择已有库，再输入该库密码解锁。服务器不接收库加密密码原文，只保存密文密钥包。刷新访问 key 不改变库加密密码或内容主密钥，已有设备重新授权时保留解密材料、原绑定、任务和暂停状态。库名默认取本地文件夹名，内部以稳定 vault ID 绑定，不因同名自动合并或因文件夹改名换库。所有设备解密材料及密码均丢失时，管理员无法恢复笔记。

交互预览为 `design/admin-plugin-demo.html`，同页切换后台与插件，共享仅在内存中的虚构数据，刷新重置，不联网、不读取真实笔记、不执行加密或系统安全存储。覆盖后台登录、创建用户/一次展示 key、刷新/停用/恢复/删除、插件授权、创建库、已有库解锁、暂停恢复及授权/密码/网络/保存错误。场景选择器会重置示例用户和库，便于独立审阅；自定义操作流程可直接切换两端继续体验。

用户只授权 HTML demo，本轮未修改插件、服务端、协议或部署代码；两种凭据分离和后台、多用户、多库均不属于当前实现。原多库稿保留供比较，其中“同步密钥携带库 ID 并兼任解密”的建议被本节新方案替代；切换限制、首次接入已有本地文件的交互细节仍以新 demo 审阅结果为准。

## 多库设计预览（旧方案保留，未实现）

用户要求先基于现有 HTML 审阅一个 Server 支持多个同步库的交互，暂不修改插件或服务端。独立预览见 [多库连接 HTML](../design/connection-multi-vault.html)，原连接稿保留。

本轮建议：一个服务承载多个独立加密、授权和同步进度的库；接入密钥封装库 ID，保持名称/地址/密钥与同行保存并测试。显示当前绑定库，验证反馈增加同步库识别。异库密钥验证后展示原目标对比，确认前不替换绑定。原库有未完成任务时要求先处理；本地已有文件时引导在新的空白 Obsidian 库接入，已有文件迁移另行设计；空白且无待处理任务时允许明确确认后更换并保留暂停状态。以上交互限制和密钥格式均待用户评审，不能视为已确认合同或现有能力。

HTML 仅使用虚构数据，不连接服务器、不读写真实笔记、不保存真实密钥，也不构成多库隔离、安全存储或故障恢复的验证证据。

## 压缩后的恢复连续性与升级补证（工作区已实现，尚未发布）

全局序号和 epoch 不足以发现旧备份：其他设备可能把恢复后的序号推进到客户端已见值以上。当前头基线凭据只证明某修订曾被接受，也不能证明该修订的后续修改仍在恢复后的数据库中。因此新增强制协商 `device-continuity-v1`，每设备只保存一个可替换随机标记，不增加永久历史链。

- PG `device_continuity` 的标记与提交、接收日志、创建/复用冻结快照、基线认证在同一事务内做 From/Next CAS；失败则一起回滚。其他设备的提交不能推进本设备标记。客户端 schema v8 保留已确认标记、至多一个 pending 标记和升级补证状态，先持久化 pending，再请求服务端；确认标记持久化后，调用方才可接收结果、移除 outbox 或应用文件。
- 请求超时后不直接丢弃 pending。若服务器仍处于 From，客户端通过独立 fence 事务推进到原 pending，使尚未到达的旧请求 CAS 失败；若旧请求已先完成，则读取其相同 Next。响应丢失和事务/进程中断均可重试。未知标记要求恢复核对，保留本机字节、队列和恢复证据，不能用重置标记/游标绕过。
- 只读检查可显式使用 `X-Sync-Read-Only: 1` 获取日志、基线或快照，不能提交修改，也不能作为自动文件应用入口；实际同步引擎始终使用连续性保护。只读检查不会使另一个活动客户端的标记失效。同一设备身份复制成两个独立活动数据库仍不受支持。
- 旧数据库升级首次引入连续性标记时，先逐一认证已有展示基线、远端头、待应用及待提交所依赖的准确修订；不把当前远端头当作旧展示基线。正在 outbox 中创建的修订不伪装成已接受版本。认证全部成功后才结束补证；未知基线保留升级状态并要求核对，中断后继续。普通 compact 应用缺少凭据时主动补证，不再无错误地永久跳过。
- 本机数据库丢失但设备身份仍在时，空队列可通过只读 `GET /metadata/migrations` 恢复已完成的一次迁移标记，不重发不同摘要的空包，也不重开旧登记。非空未知包仍须原摘要匹配；原登记内容与服务端约束保持不变。没有已接受元数据的全新数据库可采用当前连续性标记，随后对实际文件做已有的匹配收敛或独立分支处理，不能凭文件时间猜祖先。

联合备份必须保留完整 PG 连续性标记和设备本机持久状态。已有标记可以阻断“同 epoch、序号追平”的服务端回退；首次升级只能对服务器仍能认证的准确旧基线补证，不能追溯此前从未保存的连续性证据。实现和隔离恢复测试不等于生产还原工具或手机真机验收。本决策继续只服务同步与冲突安全，不增加历史版本、历史恢复或回收站。


## 本机租约的续期与恢复边界（工作区已实现，尚未发布）

同步和显式冲突解决共享相同续期规则：续期事务只能延长仍属于本执行、且尚未过期的租约，不能用首次获取逻辑重新获取消失或过期的租约。设备暂停期间另一执行可能已经获取、完成并释放，表中没有竞争者不代表旧执行仍有权限。失去租约后停止文件应用和清理，保留 journal、暂存和不可变队列；新的执行重新取得租约并从持久状态核对恢复。结束时先停止并等待已发出的续期事务，再释放租约，避免迟到续期复活已结束的执行。冲突提交和后续应用、清理都受续期保护。

本机完整旧数据库备份也必须恢复其连续性标记。服务器已经接受该设备后续视图时，旧标记不匹配就要求核对，不自动重置；当前文件中的新字节继续保留。这与本机数据库完全丢失后的无基线核对不同。自动测试恢复完整标记并断言阻断，不能只恢复部分基线表来宣称完整备份恢复。
