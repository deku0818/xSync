# 安装与接入 xSync

当前为 **0.1.2 初始版本**，已发布到 [Obsidian 社区目录](https://community.obsidian.md/plugins/xsync)，版本文件见 [Releases](https://github.com/deku0818/xSync/releases)。普通库初始化与设备接入已实现；首次使用先选独立测试库和备份。旧 0.0.x 是预置身份的实验环境，不能通过改名把旧服务器数据当成新库。

## 服务器由谁初始化

在**自己的电脑**运行，需 Node >=22.12 和本项目依赖：

```sh
npm ci
npm run server:init -- --out .local/xsync-owner
```

命令创建新的私有目录，已有目录会拒绝覆盖：

- `server.json`：同步库 ID、epoch、密文密钥包和接入验证公钥。只把这个文件送到服务器。
- `sync-key.txt`：随机生成的 256 位同步密钥，只保存在自己的设备和离线备份中。命令不打印密钥，也不联网；不要把整个目录上传到服务器、GitHub 或共享笔记库。

同步密钥丢失且所有设备的保护记录也不可用时，服务端无法恢复明文。服务器运行、HTTPS 和数据库配置见[自建服务](DEPLOYMENT.md)。

## 安装插件

在 Obsidian 的“设置 → 第三方插件 → 浏览”中搜索 **xSync**，安装后启用。也可打开[社区展示页](https://community.obsidian.md/plugins/xsync)，点击 **Add to Obsidian**。

手动安装使用 GitHub Release 中的 `main.js`、`manifest.json` 和 `styles.css`，放到测试库的 `<配置目录>/plugins/xsync/`。开发构建可在仓库根目录运行 `npm run package:plugin`；产物位于 `dist/release/`，ZIP 内为 `xsync/` 文件夹。默认配置目录是 `.obsidian`。最低宿主版本暂设为 **1.14.4**；这不是对所有较新版本或平台的兼容保证。当前插件界面为中文。

已有 `obsidian-sync-dev` 的测试库：先禁用旧插件，不要同时启用两个同步实例。新插件 ID 不会自动迁移旧插件设置，也不会自动安装、更新或卸载插件。原实验服务、设备身份和 IndexedDB 不能与新建服务混用；保留旧数据，另建测试库验证新接入流程。之前的探针是独立插件，不是 xSync 的依赖。

## 第一台与后续设备

打开普通测试库，插件会创建本机设备 ID 和 IndexedDB ID，不需要开发标记、`device.json` 预置令牌或测试脚本。打开 xSync 设置，填写客户端名称、HTTPS 服务器地址与同步密钥，点击“保存并测试”。

密钥只在本机解开密钥包。客户端签署一次性接入挑战，本机安全保存待确认凭据后才提交授权；服务端不接收同步密钥、会话解密密钥或 Bearer 令牌原文。设备名由服务端原子判重，不会自动改名。保存成功后前台自动同步；已有不同内容的同名文件仍需要冲突审阅，不自动覆盖某一端。

全新服务允许持有密钥的第一台设备接入。此后接入默认关闭，管理者需在服务器临时开放窗口：

```sh
./xsync-server --config /srv/xsync/server.json --enroll-for 10m
```

在窗口内配置手机或另一台电脑。完成后立即关闭：

```sh
./xsync-server --config /srv/xsync/server.json --enroll-for 0
```

以上管理命令需要与运行服务相同的 `XSYNC_DATABASE_URL` 和配置；不重启服务，也没有公网管理接口。窗口最长 1 小时。接入回执或本地设置指针写入失败时，重新输入同一密钥并保存会重试原授权请求，保持设备身份和令牌；不会凭上传顺序选择文件版本。

## 日常操作与凭据恢复

已保存密钥用固定圆点占位，实际输入框为空；留空可复用受保护记录。暂停/恢复保留配置，重开仍暂停。iOS 回到前台或网络恢复后自动补齐，不承诺锁屏、后台持续运行。

普通设备身份文件只包含设备 ID 和 IndexedDB ID。同步会话、授权令牌和待确认接入请求放在设备安全存储保护的记录中；公开设置仅保存地址、库 ID 和记录指针。不要复制设备身份、IndexedDB 或保护记录来添加第二台设备。

安全存储暂时不可读时保留原记录，回前台重试。永久丢失授权凭据但仍有同步密钥时，管理者临时开放窗口后可重新保存，为同一设备 ID 更换令牌；旧令牌失效，已有因果关系与队列身份保留。若本机 IndexedDB 或其他恢复状态也损坏，应先核对数据，不能静默重建身份掩盖问题。

## 撤销设备

```sh
./xsync-server --config /srv/xsync/server.json --list-devices
./xsync-server --config /srv/xsync/server.json --revoke-device <device-id>
```

列表仅输出设备 ID、名称和撤销状态。撤销状态持久化；该 ID 不能重新授权，名称和历史修订仍保留。撤销后新的 HTTP 请求被拒绝，旧事件票据及连接在下次提示/心跳核对时失效；已进入执行的请求不是跨系统原子撤回。

**撤销服务访问不会让设备忘记已经得到的同步密钥或明文。** 持有共享密钥的人在另一次开放窗口中仍可能以新 ID 接入。密钥泄露需要更换库密钥及迁移数据，当前尚无自动密钥轮换工具；不要把撤销描述成内容密钥轮换。

## 平台与发布边界

Mac 使用 Electron safeStorage；iOS 使用当前适配的宿主原生 Keychain 桥接，不提供明文回退。桥接是内部接口，需要按宿主版本验证。Android 尚无安全存储适配；Windows/Linux 的实现路径未完成真机验收，不能视为正式支持。

旧版本已做过 Mac/iPhone 同步和前台恢复验证。**0.1.2 新接入、包含令牌的保护记录、xSync ID 与包安装尚须重新做 iPhone 真机验证。** 联合备份实际还原、生产安全审查、大附件峰值内存、系统终止/迁移边界也尚未完成。社区提交步骤见[发布准备](RELEASING.md)。
