# 安装与接入 xSync

本文对应尚未发布的管理后台版本，插件与服务端须从同一提交构建；已发布的 0.1.2 仍使用旧接入流程。新模式仅支持全新部署和新库，不自动迁移已有服务器、设备身份或笔记库绑定。

## 两类凭据

- **访问 key**：管理员在后台创建用户时生成，每位用户一个有效 key，仅生成时展示一次。它允许访问该用户所属的同步库，不用于解密笔记。
- **库加密密码**：用户创建每个同步库时在插件本机设置。它保护随机库主密钥，服务器只保存密文密钥包，不接收密码原文。不同库相互独立。

管理端密码只用于管理网页，与以上两类凭据不同。管理员无法查看或恢复库加密密码。所有设备的解密材料及密码都丢失时，原内容无法恢复。

## 管理员准备

按[部署说明](DEPLOYMENT.md)启动全新服务。浏览器打开 `https://sync.example.com/admin/`，用部署时设置的管理密码登录。

1. 点击“创建用户”，填写备注名。
2. 保存并交付只展示一次的访问 key。列表只显示末尾，关闭后不能再次查看完整值。
3. 用户可以持同一 key，在自己的多台设备与多个库使用；不同用户互相隔离。无需开放接入窗口或执行库初始化命令。

本轮不提供空间统计、容量配额、用户注册或团队共享。

## 插件首次连接

构建插件 `npm run package:plugin`，将产物安装到独立测试库的 `<配置目录>/plugins/xsync/` 并启用。最低宿主版本为 1.14.4。此版本尚未发布到社区目录，不要用旧 Release 文件配套新服务端。

1. 打开 xSync 设置，填写客户端名称、HTTPS 服务地址和访问 key，点击“保存并测试”。
2. 授权成功后，选择已有库或创建新库。库名默认取当前本地文件夹名称；内部使用固定库 ID，文件夹改名不改变绑定，同名不会自动合并。
3. **创建新库**：填写库名、设置并确认至少 8 个字符的库加密密码，确认已备份后创建。插件先保护本机解锁材料，再发布库初始化信息并开始上传。
4. **接入已有库**：明确选择目标库，输入创建该库时的加密密码并确认。授权有效不代表已经解锁；密码错误不上传或覆盖数据。

同一库中的客户端名称唯一。已有本地文件会保留，重叠修改进入冲突审阅；不按时间或设备优先级覆盖。更换用户或另一个库时，在新的空白 Obsidian 库接入，原绑定和任务保留。

连接配置、授权令牌、访问 key 与本机解锁材料由系统安全存储保护；公开设置只存地址、名称、库 ID 和保护记录指针，不明文保存凭据。已保存访问 key 显示固定圆点占位，实际输入值为空，留空复用。日常只需暂停／恢复，重开仍保持暂停。

## 刷新、停用与删除

- **刷新访问 key**：旧 key 和旧设备授权失效。各设备重新填写新 key，沿用原库、解密材料、待处理任务和暂停状态。设备令牌也会更新，旧令牌不会因重新授权而复活。
- **停用用户**：阻止该用户所有设备的新请求；保留远端数据与本地笔记。恢复后，持当前有效授权的设备可重新同步。
- **删除用户**：输入用户名确认后，立即撤销访问，删除所属远端库。文件系统清理中断时根据持久删除标记重试。设备上已有明文和本地文件不会远程擦除。

已经开始执行的请求不承诺原子撤回；事件连接在下一次提示或心跳核对授权。刷新访问 key 不会更换库加密密码，也不能让已获得明文或解密材料的设备忘记这些内容。

## 平台边界

Mac 使用 Electron safeStorage；新接入流程已在同一 Mac 的真实 Obsidian A/B 独立测试库验收。iOS 使用宿主原生 Keychain 桥接，没有明文回退，仍需 iPhone 真机验证；Android 尚无安全存储适配，Windows/Linux 尚待真机验收。两台物理设备的验证不由同机双库测试替代。

支持前台同步和回前台补齐，不保证锁屏或持续后台运行。大附件源文件仍整读。生产备份还原、资源峰值、内容密钥迁移与安全审查仍需验证。
