# 0.0.4 配置与暂停验收

日期：2026-10-14，Asia/Shanghai。仅操作既有生成的 A/B 独立测试库，不使用真实笔记库，不部署服务。沿用运行中的本机 Go 服务与专属 Docker PostgreSQL。

## 产品合同与实现

用户填写服务器地址、同步密钥并保存，之后自动连接和同步。日常只有暂停/恢复同步；暂停保留配置与密钥，重开后仍暂停，恢复不重新输入密钥。移除记住解锁、锁定并忘记、独立解锁与手动核对入口。

当前“同步密钥”对应实验库已有加密口令，不发给服务器。服务端仍使用测试工具预置的设备授权；本轮不是任意服务器/新设备通用接入能力。Windows/Linux、手机以及正式配对和凭据轮换仍待完成。

保存时先验证 HTTPS/本机地址规则、远端库/设备/epoch、密钥以及已知密钥包锚点。新密钥材料由 OS safeStorage 保护，写到不可变随机命名记录并读回校验后，才保存 data.json 对该记录的引用。设置仅含地址、暂停状态和本地记录名，无明文密钥。错误密钥/身份或引用保存失败时旧配置仍可使用；新产生的无引用密文文件暂保留，不清理旧记录，不迁移加密格式或清空数据库。

format=1 旧安全记录继续读取，旧手动锁定/不记住选择保留；显式保存后转为 format=2。暂停停止实时连接与自动调度，已运行的任务安全结束；排队同步和显式冲突提交会重新检查暂停状态。本地重命名仍只记录位置意图，恢复后提交。

## 真实 Obsidian UI

Obsidian 1.14.4，同机 A/B 独立 Vault、真实 IndexedDB 与当前 Mac safeStorage：

1. 更新两库插件文件为 0.0.4，分别禁用/启用插件加载新构建；保留笔记、DB、配置与设备身份。
2. B 设置页只展示地址、同步密钥、保存与暂停/恢复；旧三项入口消失。将地址改为 `http://localhost:8873`，用公开测试密钥保存成功；密码框清空并提示“已保存”。输入错误格式的地址时保存失败，原配置保留。
3. B 点击暂停，按钮变为恢复；重载 B 插件后仍显示该地址、密钥已保存和“恢复同步”，没有再次输入密钥。
4. 在 B 暂停时创建假笔记 `暂停恢复验证-0.0.4.md`；检查 A 中不存在该文件。
5. 点击 B 恢复，未重新输入密钥；该笔记自动到达 A，实际文件字节一致。
6. 重载 A 后原 format=1 受保护记录自动恢复，设置显示密钥已保存，无需重新输入；A/B 自动同步保持开启。

本轮真实 UI 验证了插件重载，不是 OS 重启、整个应用退出或物理双机验证。未重复把 0.0.3 的弱网重连/全部冲突过程当成本轮 UI 验收，原有证据保持独立。
