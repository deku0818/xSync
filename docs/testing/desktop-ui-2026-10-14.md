# 真实 Obsidian 双库 UI 验证

日期：2026-10-14（Asia/Shanghai）。环境：同一台 Mac，macOS 27.0.1，Obsidian 1.14.4，两个独立 Vault / 窗口与各自真实 IndexedDB；Go HTTP 开发服务与 Docker PostgreSQL。两端自动核对均关闭，按步骤手动触发同步。

所有创建、编辑、选择、确认和同步均通过真实 Obsidian UI 执行；文件读取/哈希和服务端只读快照用于补充核验。只操作本项目生成的 `ObsidianSync-电脑A` / `ObsidianSync-电脑B`，没有修改真实笔记库。

## 实际结果

| 场景 | 实际操作与观察 | 结果 |
| --- | --- | --- |
| B 首次加载 | 在 Obsidian 中打开 B，信任自建测试库并加载开发插件；输入公开测试口令，核对后待上传/待应用/冲突为 0 | 通过 |
| A → B | A 编辑器保存“UI 往返 1：电脑 A 编辑，发送到电脑 B。”；A 同步，B 同步，B 编辑器显示准确内容 | 通过 |
| B → A | B 保存“UI 往返 2：电脑 B 修改后回传到电脑 A。”；B 同步，A 同步，已打开的 A 编辑器随 Vault.process 更新 | 通过 |
| 并发与差异 | 双方基于往返 2 的共同版本先各自修改，再依次同步；双方仍保留各自字节，A/B 显示需处理；比较页显示准确设备名称、修订 ID、快照和文本差异 | 通过 |
| 暂不处理 | A 关闭比较页，保留冲突；新建并同步 `冲突期间继续同步.md`，B 收到其实际内容，同时冲突文件仍需处理 | 通过 |
| 过期选择 | A 比较页选定 A 快照但暂不确认；B 继续修改并同步；A 确认旧选择得到 `REVIEW_STALE`；重新比较包含 B 最新内容 | 通过 |
| 保留双方 | 重新比较后明确选 A 沿用 `同步试验.md`，B 的最新内容保存为 `同步试验-保留电脑B.md`；B 同步后两份均正确，没有重复副本 | 通过 |
| 使用某一方与显示修复 | 更新插件后重复并发，明确选 B 快照；A 编辑器更新，面板/状态栏立即一致地显示普通文件同步完成；B 再核对后待上传/待应用/冲突均为 0 | 通过 |

“并发”是两端关闭自动同步、在同一基线先编辑再提交；本轮没有断开物理网络，不把它报告为断网测试。

## 本轮发现并修复

解决冲突后，原实现直接调用核心 `engine.resolve`：新面板读取到冲突已清零，但底部状态栏只由普通 `sync` 更新，仍显示“需处理”；旧同步面板同时留在比较页下方，关闭新面板会看到旧状态。

修复位于 `plugin/src/sync-main.ts`：解决操作通过宿主 `resolveConflict` 统一协调，成功/拒绝后读取当前状态并刷新状态栏；进入比较页前关闭旧面板。同步版本和用户选择语义没有改变。新增两项回归测试覆盖成功解决后立即刷新，以及旧选择被拒后继续显示需处理、释放宿主执行门闩。

真实 UI 再次制造并发、选择 B 后复测通过，无需额外点击同步来刷新 A 的状态栏；比较时旧同步面板已关闭，解决后只有一层新面板。

## 文件与历史核验

最终两个库中的四份 Markdown 文件逐字节相等，SHA-256 见 [机器核验记录](desktop-ui-results-2026-10-14.json)。最终服务端提交边界为 13。

- `同步试验.md`：第二轮明确选中的 B 快照，“UI 修复复测：电脑 B 新分支，明确选择后应立即刷新状态。”
- `同步试验-保留电脑B.md`：第一轮审阅期间 B 新增的完整快照。
- `冲突期间继续同步.md`：未解决冲突期间仍能传输的独立笔记。UI 操作期间产生的额外空行也经后续核对同步，两端最终字节一致。
- `开始使用.md`：两端原有测试说明。

服务端冻结快照确认：第二轮未选的 A 修订仍存在，新的解决修订以 A/B 两个准确头为父，并记录所选 B 的来源。此为历史数据仍保留的核验，不表示历史浏览界面已经实现。

## 验证边界

更新后 `npm run check` 的 32 项默认测试、类型检查与两种插件构建通过；`npm run test:desktop` 的 8 项真实 Docker PG 合同/race 和 8 项双客户端集成通过。

此次 UI 验证使用真实 IndexedDB、Vault API、编辑器、网络和数据库，补上此前 fake-indexeddb 双客户端测试的宿主边界。但它仍是同机双库，不是两台物理电脑、Windows/Linux 或 iPhone；没有覆盖全部进程强杀/断电、完整附件/整库配置、目录、历史界面或备份还原。

两个测试库、开发插件和本地开发服务保持可用，自动核对保持关闭，方便用户继续手动检查。
