## 开发入口

要求：Docker（含 Compose v2）已运行、Node >=22.12、Go >=1.27。编译器依次取 `OBSIDIAN_SYNC_GO`、项目 `.local/toolchains/go/bin/go`、PATH 中的 `go`；新机器安装 Go 即可，也可通过变量指定路径。没有任何本地 PostgreSQL 二进制要求。

```sh
npm ci
npm run desktop:setup
npm run desktop:start
```

`setup` 启动专属 Compose 数据库、构建插件/Go 服务、准备库和独立凭据。`start` 前台运行 HTTP 开发服务。已有进程在 8873 时不要再启动第二份。

数据库：`server/compose.dev.yaml`，Compose 项目名 `obsidiansync-dev`，PG 镜像 `postgres:17.11-alpine`，端口 **127.0.0.1:55438**，数据在 Docker volume `obsidiansync-dev_postgres-data`。仅本项目资源，不操作其他容器/volume。

Go 开发 API：**127.0.0.1:8873**。配置在 `.local/desktop/server.json`，对象目录 `.local/desktop/objects`；凭据文件不进 Git。不向公网/局域网直接开放 HTTP 或数据库。

停止数据库用 `npm run desktop:stop-db`，保留数据；服务终端用 Ctrl+C 停止。`docker compose ... down -v` 会删除测试数据库，日常不要使用；如需重建必须同时保留/核对客户端本地状态，不能仅清数据库后继续当成同一库。

## 按钮含义

- **服务器地址 / 同步密钥 / 保存并测试**：校验远端身份与密钥后安全保存，自动连接。设置中不保存明文密钥；本地普通笔记仍为明文。当前仍需测试工具预置的设备授权，尚不能只靠这两个输入接入任意新服务。
- **暂停同步 / 恢复同步**：暂停上传和接收，保留配置与密钥；已执行的同步安全结束后报告暂停。重开仍暂停，恢复自动补齐，无需重输密钥。已暂停期间的重命名只记录本地 outbox，不访问服务器。
- 不再提供独立解锁、锁定并忘记、记住解锁开关或手动核对按钮。

公开测试口令为 `obsidiansync-desktop-test-only`，只适用于生成的假数据库，不能用于真实库。生产设备接入和改口令界面尚未实现。

## 双库手动验证

1. 启动开发服务，在 A、B 的插件设置分别填写地址和测试同步密钥并保存；打开双方的 `同步试验.md`。
2. A 改成“电脑 A 的版本 B”并保存，等待自动到达 B，核对实际内容。
3. 两端保持同一版本后，分别暂停同步。双方各改同一段，再分别恢复同步。
4. 预期：双方的本地内容都保留；面板显示冲突。其他新文件仍可继续同步。
5. 查看双方：显示测试设备名称、准确快照和文本差异；选择一个，再明确确认。保留双方时填写另一份最终路径，所选快照沿用原路径。
6. 比较页保持打开，在 B 继续编辑并等待自动同步，再提交旧选择：应拒绝 `REVIEW_STALE`，重新核对/比较，不能丢掉未展示分支。
7. 重命名与离线正文编辑、删除与离线编辑分别重复。注意删除路径当前仍被墓碑保留，不能直接当成新文件复用。

当前冲突 UI 只允许完整展示的短文本（每份 <=64 KiB）作选择，已支持手动合并和加密草稿。大文本/二进制尚无完整预览与导出，保持双方并提示暂不处理。内核保留版本不会等于完整附件审阅 UI 已完成。

## 第二台物理电脑

当前服务只绑定本机。需要在另一台电脑测试时，可通过已有 SSH 访问建立转发：

```sh
ssh -N -L 8873:127.0.0.1:8873 <开发服务所在电脑>
```

将 **B 测试库** 单独复制过去（不要同时在两台电脑运行同一个 B 身份），其 endpoint 继续用 `http://127.0.0.1:8873`。通过 Obsidian 打开，在插件设置填写地址与同步密钥并保存。凭据仅属于这个测试服务，不复制真实库或其他账户数据。

SSH/另一台设备连接本轮尚未运行；不把同机双客户端 E2E 写成两台物理电脑、Windows/Linux 或 iPhone 的验证。

## 自动验证及证据

```sh
npm run check
npm run test:desktop
```

- `check`：类型、59 项单元/属性/辅助测试、探针和正式开发插件构建通过；默认跳过需 Docker 的 16 项 E2E。
- `test:desktop`：Go 编译、**14 项真实 Docker PostgreSQL / 事件合同测试（含 race）**和**16 项双客户端集成测试**通过。
- Go 合同覆盖事务回滚、提交后丢回执、重开数据库连接、并发连续发布、命名空间交换、保留双方、对象 fsync/发布边界、密文不可变/损坏、鉴权/JSON 校验、epoch/过期日志。
- 双客户端用真实 Go HTTP、Docker PostgreSQL、临时真实文件目录和 fake-indexeddb；覆盖文本/附件、丢响应后继续编辑、并发/其他文件继续、过期审阅、保留双方、重命名/编辑、写后未确认恢复、新字节保护、扫描失败与删除/编辑。
- 真实 Obsidian A/B 已完成 UI 往返、并发/暂不处理/过期选择/保留双方/选用某方和显示修复复测，四份文件字节一致；[完整记录与截图](desktop-ui-2026-10-14.md)。

故障注入目前是可复现的错误边界和连接重开，不是所有边界的操作系统杀进程/断电证明。客户端 fake IndexedDB 不代替真实浏览器持久化；A/B 已实测真实 Obsidian IndexedDB 与编辑/应用/冲突路径，但强杀恢复还待验证。
