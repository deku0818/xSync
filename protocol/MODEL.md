# 同步协议语义

本文描述当前源码的同步不变量。类型与校验见 `src/types.ts`、`src/wire.ts`；完整因果图参考模型见 `src/model.ts`。参考模型仅有内存状态，不实现鉴权、SQL、文件耐久或对象回收；客户端和 Go/PostgreSQL 服务另行实现持久化。

## 身份、因果与冲突

- 文件身份、内容修订和位置修订相互独立。普通编辑以实际展示的准确修订为父；已接受的旧父仍合法，形成并发分支。删除也是不可变修订，不能压过并发编辑。
- 完整图模型以极大节点计算头集合；当前头投影从集合移除准确展示父 ID 后追加新 ID，不递归依赖历史修订正文。
- 普通内容编辑不更新位置。位置变更使用 CAS，组内操作原子提交，位置修订 ID 不复用。
- 解决冲突必须匹配完整当前头集合；带 `expectedLocation` 时同时检查位置。过期选择返回 `REVIEW_STALE`，不覆盖新分支。暂缓处理不阻断其他文件。
- 选择、手动合并和保留双方都是显式解决。保留双方支持两个头，原文件解决与伴随文件创建属于同一提交组。客户端认证审阅来源并重新加密，服务端不能验证密文对应的明文选择。
- 无法证明同路径初始内容的祖先时保留独立分支。明确拒绝的单文件创建可归档原意图后重新核对；未知提交结果或复杂移动不能推断修复。

## 请求、基线与确认

`metadata-anchors-v1` 信封绑定每设备请求流坐标、准确请求摘要与原结果。相同请求重试返回原结果，坐标不能绑定不同请求。请求序号用于回执回收和重放隔离，不参与因果判断。

基线凭据绑定 vault、epoch、file、revision、原修订摘要和签发序号，由服务端持久 HMAC 密钥认证。客户端验证身份、摘要和原修订密文清单；签发序号不能作为编辑顺序。SHA-256 摘要使用对象键排序、数组顺序保持及 Go JSON 转义规则，不接受客户端自报摘要作为真值。

客户端在同一事务保存提交结果、待发送确认并移除 outbox。服务器在确认后释放跟踪结果，并以连续前缀和稀疏区间拒绝退休序号；失败或排除的空洞不随后续成功而退休。计数回退需要核对，不能自动换坐标掩盖。

操作 ID 为 `q_<stream>_<number>`，修订/位置 ID 为 `m_<stream>_<number>_<role>_<action-index>`，角色 `r/l/rc/lc` 分开。文件 ID 独立，退休坐标不能重放或复用身份。

## 日志、快照与本机范围

成功提交组分配连续序号，失败不取号、不发布。对象必须先耐久发布，才能被提交引用。HTTP 拉取负责补齐，WebSocket 事件仅为提示。

`compact-heads-v1` 快照冻结边界，携带所有文件身份、当前头完整修订及对应凭据；空库凭据可省略，检查点不得超过边界。客户端在同一事务保存凭据、投影和游标，再拉取边界后的增量。日志过期返回 `NEED_SNAPSHOT`，epoch 变化返回 `EPOCH_CHANGED`，不能自动重置库。

`snapshot-pages-v1` 通过 `X-Sync-Snapshots` 协商。分页始终读取同一冻结快照及设备租约，每页最多 256 项且编码不超过 24 MiB；客户端校验边界、总数与连续分页游标，全部读完才原子接收。快照不再以总文件数或单次响应大小限制整库恢复。单项超限时保留日志并报告 `logDeferred`，其他满足依赖条件的回收继续进行。

接收游标与远端元数据/inbox 同事务持久化。applied 表示本机所选范围已应用或按规则跳过的连续边界，不表示整库内容已写入。排除不产生远端删除，规则改变后从已接收状态补齐，保留本机队列和应用日志。

未完成组之间的连续已完成 inbox 可压成一个完成端点，不再保留正文；未完成组及 applied 连续边界不变。被拒绝的显式解决意图保留到后续本机显式选择替代它，且替代修订实际应用后的确认事务成功；其他设备解决冲突或时间经过都不能单独触发删除。

配置的协议逻辑命名空间固定为 `.obsidian`；`ObsidianVaultPort` 按实际 `Vault.configDir` 双向映射物理目录。该命名空间参与加密路径身份，不能随设备目录名改变。

## 密文对象与回收

`addressed-objects-v1` 区分原 64 位十六进制随机 ID 与新 `c_<SHA256>` ID；新哈希覆盖完整密文字节。新 envelope 的版本为 1，XChaCha20-Poly1305 AAD 绑定 `object-v1/vaultId/keyEpoch`，保留随机 nonce，由 manifest 认证准确对象列表。旧 envelope/AAD 保持读取兼容，不能仅换 ID 前缀转换格式。

公开 ID 与随机物理 `storage_token` 分离，读取、快照、上传尝试和删除任务绑定物理标识。创建文件前复查上传登记；内容及临时链接耐久删除后才释放相应恢复登记，旧删除任务不能影响新存储标识。

当前头、未解决冲突、保留日志、活动快照和上传/下载保护决定内容保留。新格式对象身份可在内容删除完成后回收；旧格式摘要、旧接受证据、删除/撤销身份及未完成恢复证据仍可能保留。同步不提供历史版本或回收站，不能据此承诺所有元数据恒定。

## 设备连续性

`device-continuity-v1` 要求 handshake 的 `continuity: true`。每设备持有一个随机 64 字符十六进制标记；受保护请求以 `X-Sync-Continuity-From/Next` 与数据事务一起 CAS，响应返回 `X-Sync-Continuity-Token`。客户端先持久化 pending，确认后才接受数据。

超时请求通过 `POST /metadata/continuity/fence` 将同一 From 推进至同一 Next，拒绝迟到原请求。未知标记要求核对，不自动复位。其他设备不能推进该标记，因此全局序号追平不能掩盖旧数据库回退。只读检查不能用于自动应用文件。

升级前准确基线逐一认证，全部完成才退出 bootstrap。旧队列保持不可变并一次登记；已完成迁移后的空队列可读取完成状态，不能借此登记未知旧意图。同一设备身份不能复制到两个独立活动数据库。

## 验证与兼容

`tests/protocol/` 使用定向场景与 fast-check 随机历史，`head-shadow.test.ts` 对照独立完整图 oracle。真实数据库、故障恢复与原生 IndexedDB 测试见[开发流程](../docs/testing/DEVELOPMENT.md)。模型测试不能证明文件耐久、原生安全存储或生产备份恢复。
