# 协议语义模型 v0

状态：2026-10-14，实验性可执行参考模型。已有配套的实验 HTTP 校验、Go/PostgreSQL 服务和客户端，开发步骤见 `docs/testing/desktop.md`；下文的“不实现持久化”等限制专指这个内存参考模型。`src/types.ts` 是内部类型，不是冻结的 HTTP / JSON Schema / 加密格式。`VaultModel` 只有内存状态；没有鉴权、SQL、文件耐久、对象上传、GC 或网络服务。

## 本轮固定的可测试语义

- `fileId`、内容 `revisionId` 和 `location.revision` 独立。ID 由调用者提供；生产端需要随机生成并限制编码。模型用可读 fixture ID。
- 普通编辑只能以一个准确的 `displayedRevision` 为父；父修订必须属于该文件。旧父合法，形成并发分支。普通编辑不能冒充多父解决操作。
- 头集合是因果图的极大节点；新修订只移除自身祖先中的头。删除同样是一份不可变修订，不能压过并发编辑。
- 普通内容修改不更新位置。位置使用 CAS；一个组可原子交换两个已占路径，失败则整个组不发布。位置版本 ID 不可复用，避免 ABA。
- 创建需要显式位置。空文件、空目录、删除分别建模；目录不能携带文件块。
- 解决要求 `observedHeads` 与当前完整头集合相等，集合中不能重复。新分支到来后返回 `REVIEW_STALE`，保留所有历史和当前分支。暂不处理就是不提交解决；不锁住其他文件。
- select / manual / keep-both 都是显式解决意图。keep-both 本轮只支持恰好两个头：调用者提供固定 companion file/revision/location ID、准确来源和重新加密的 manifest，原文件解决和伴随文件创建属于同一组。
- 选择操作记录 `selectedFrom`。服务端无法验证密文代表的明文与用户审阅快照相同；最终客户端必须认证来源并重新加密，因为 manifest 绑定 file/revision/parents。模型只核对对象引用顺序、种类和 keyEpoch，没有实现 AEAD 格式。
- `(deviceId, opId)` 绑定实际规范化请求体。对象键排序，数组顺序保持；重试返回首次回执，换请求拒绝。模型保存完整 canonical body 比较，网络摘要算法尚未冻结，不接收调用者自报摘要作为真值。
- 引用对象必须先声明耐久。`declareDurableObject` 只是测试前提，绝不证明 fsync 或摘要校验已实现。
- 每个成功提交组分配一个连续 seq，事件包含整组操作。失败不取号、不发布、不改变历史。模型用复制后发布表示事务；真实 Go/PostgreSQL 要在每库行锁和同一事务中重做合同测试。
- 快照是冻结拷贝，边界 B 后从 B 拉取增量。日志过期返回 `NEED_SNAPSHOT`；旧 epoch 返回 `EPOCH_CHANGED`；未知协议或必需特性拒绝。没有自动重置库的路径。
- inbox 任务与 received 游标一起登记；完成可乱序，applied 只越过连续已完成组。冲突或失败时不显示完成。

## 有意保守的 v0 限制

墓碑仍保留路径占用；安全释放路径、同路径重新创建和目录整棵操作的合同待后续设计。本轮不允许自动复用删除路径。位置 CAS 失败只返回错误，客户端候选意图的持久化尚未实现。

模型输入是受 TypeScript 检查的内部对象，非不可信 HTTP 入口；不应直接暴露给网络。正式阶段还需运行时 schema、大小/深度限制、opaque ID 编码、设备注册与实际名称、密文认证上下文、能力协商细节和跨语言向量。

尚未实现文本差异、冲突 UI、三方自动合并、outbox、Vault 应用日志、幂等结果保留期限、历史/对象回收、授权撤销及真实备份恢复。`InboxModel` 的复制发布不是 IndexedDB 持久化实现；探针的 Dexie 事务只验证底层能力。

## 如何验证

`npm test` 包含定向场景及 fast-check 随机历史。图头 oracle 独立从父关系计算极大节点，覆盖 2–5 个设备标识、离线旧父、删除和重试；固定种子便于重现。失败时保留 fast-check 的 seed/path，再缩减为回归场景。通过这些测试只说明所覆盖的模型性质，没有证明生产实现或所有协议性质。

Go + 真实 Docker PostgreSQL / 不可变对象后端已有 8 项合同测试，客户端有 8 项双客户端集成；完整随机历史的跨实现对照、全部持久化边界进程强杀仍待完成。


## 0.0.6 本机范围与独立接入

规则在每个客户端独立生效，排除保留 localFile/outbox/apply journal，不产生删除。received 游标与远端元数据/inbox 一起持久化；兼容字段 applied 表示本机当前范围已应用或按规则明确跳过的日志边界，不表示所有文件均已写入 Vault。跳过项有本机状态，远端文件/修订继续保留；规则改变后扫描全部已接收远端状态补齐，不依赖重放旧游标。UI 只报告“所选范围”，不宣称整库收敛。

branch 操作向既有文件加入无父的独立修订，用于没有可证明祖先的同路径初始内容，保留既有头。明确被服务端以 PATH_OCCUPIED 拒绝的单文件 create 可在完整归档旧 intent/身份/journal 后重新核对；精确相同字节接入已知修订，否则保留独立分支。复杂移动或未知提交结果不推断修复。resolve 包含 expectedLocation 时同时对位置修订作 CAS，正文头未变但发生重命名也会拒绝过期决定。
